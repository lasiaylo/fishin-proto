# PRD: Lure XP

## Context

Right now, when players reel the lure, there is a chance that they will not hook any fish. This doesn't feel great. We want the player to feel progress even if little occurs in the game and to get them into a calm loop of cast, reel, repeat. 


## Requirements

- Add a Lure Level and Lure Experience stat. Each lure has their own level and experience. As of now, the actual effect of leveling up a lure is yet to be determined.
- Players will earn Lure Experience whenever they go fishing with a particular lure. They can earn XP in three different ways:
    - For each x distance that the reel is lured
    - For each fight that's won
    - For each fight that's lost (less than winning)
- We need to have these XP values and the leveling requirements to be easily adjustable.
- The economy model needs to keep track of lure XP / LVL changes. This will make figuring out values to be easier.
- Display this value:
    - The lure selection dropdown should how the lure's current level, i.e. Bobber Lvl. 5
    - Under the lure selection drop down, show a progress bar showing the progress to the next level. Increment this at the end of each reel in.

## Solution

A new `lureXpStore` (Zustand) holds XP and level per lure ID as a flat `Record<lureId, { xp, level }>`. This keeps lure progression separate from the player stats and shop upgrade stores, which deal with purchase-based progression.

XP config lives in `util/constants.ts` alongside existing game tuning values:
- `XP_PER_DISTANCE` — XP per unit of distance reeled during the luring phase
- `XP_WIN` — XP awarded on a won fight
- `XP_LOSS` — XP awarded on a lost fight (less than `XP_WIN`)
- `LURE_LEVEL_XP` — array of cumulative XP thresholds, one entry per level boundary (e.g. `[100, 250, 500, 1000]` means level 1 unlocks at 100 XP, level 2 at 250, etc.)

**Earning flow in `PondView`:**
- Distance XP: `handleReelIn()` already knows `initialDistance - luringDistanceRef.current` (total distance reeled that cast). Award `distanceReeled * XP_PER_DISTANCE` to the active lure at that moment.
- Win/loss XP: `finishFight()` awards `XP_WIN` or `XP_LOSS` to the active lure, then recalculates that lure's level from cumulative XP vs `LURE_LEVEL_XP`.

XP and level-up are computed in one helper inside `lureXpStore`: `addLureXp(lureId, amount)` → updates XP, recomputes level, returns whether a level-up occurred.

**Display in `InventoryView`:**
- The `Select.Item` for each lure reads `lureXpStore` and formats the label as `"Bobber Lvl. 5"`.
- Below the `<Select.Root>`, a thin progress bar shows `(xp - xpAtCurrentLevel) / (xpAtNextLevel - xpAtCurrentLevel)`. It updates reactively whenever `lureXpStore` changes — no extra animation needed beyond the wallet counter already in the view.

**Economy model:**
`EconomyRound` gets two new fields: `lureLevels: Record<string, number>` and `lureXp: Record<string, number>`. Inside `simulateEconomy`, a local `lureXp` map accumulates XP per round using the same constants, estimating distance from `perCastOverhead` and win/loss rates from `evalLure`.

```
┌─────────────────────────────────────────────────────────┐
│ PondView                                                │
│  handleReelIn() ──► addLureXp(lureId, dist * XP/dist)  │
│  finishFight(WIN) ─► addLureXp(lureId, XP_WIN)         │
│  finishFight(LOSS) ► addLureXp(lureId, XP_LOSS)        │
└───────────────────────────┬─────────────────────────────┘
                            │
                    lureXpStore
                  { lureId → {xp, level} }
                            │
            ┌───────────────┴──────────────┐
            │ InventoryView                │
            │  dropdown label: "X Lvl. N"  │
            │  progress bar: xp % to next  │
            └──────────────────────────────┘
```

## Implementation Plan

### Phase 1 — Config constants
Add `XP_PER_DISTANCE`, `XP_WIN`, `XP_LOSS`, and `LURE_LEVEL_XP` to `util/constants.ts`.

### Phase 2 — `lureXpStore`
Create `stores/lureXpStore.ts` with state `Record<string, {xp: number, level: number}>` and an exported `addLureXp(lureId, amount)` action that updates XP and recomputes level against `LURE_LEVEL_XP`.

### Phase 3 — Wire XP earning in `PondView`
- In `handleReelIn()`, compute `distanceReeled = initialDistance - luringDistanceRef.current` and call `addLureXp(selectedLure, distanceReeled * XP_PER_DISTANCE)`.
- In `finishFight()`, call `addLureXp(selectedLure, result === Outcome.WIN ? XP_WIN : XP_LOSS)`.

### Phase 4 — Display in `InventoryView`
- Subscribe to `lureXpStore` and read the current lure's level.
- Change each `Select.Item` label from `u.name` to `u.name + " Lvl. " + level`.
- Below `<Select.Root>`, add a Radix `Progress` bar showing XP progress to the next level.

### Phase 5 — Economy model tracking
- Add `lureLevels` and `lureXp` fields to `EconomyRound`.
- In `simulateEconomy`, maintain a local `lureXpMap: Record<string, number>` and compute XP per round from `expectedLuringTime * LURING_REEL_MAX_SPEED * XP_PER_DISTANCE + winRate * inventorySize * XP_WIN + (1 - winRate) * inventorySize * XP_LOSS`. Derive levels from `LURE_LEVEL_XP` and snapshot both into each `EconomyRound`.
