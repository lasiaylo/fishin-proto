# PRD: Day Cycle + Prestige
## Context

The game right now provides only one way to progress through shop upgrades. What would be more fun would be to have a meta-progression system that allows players another layer to strategize: prestiging.
We will have prestige contextualized through a day cycle. This will give players a better sense of rhythm and more decisions, namely:
- How do I get more out of one day? 
- What prestige upgrades can I look forward to?

## Requirements
- Day Timer:
  - Each day will last 15 minutes.
  - There is a progress bar in the InventoryView showing how much time is left in the day.
  - Under this progress bar, have text showing the part of the day:
    - Night (0-5 min)
    - Dawn (5-12 min)
    - Sunrise (12-15 min)
- Prestiging:
  - The money earned on each day contributes to earning a prestige point (we'll name them dream points for now).
  - Earning a prestige point will be similar to earning levels on a lure. There will be money earned requirements in order to earn dream points.
  - Dream points can be spent on dream upgrades, that are only available for purchase at the end of day.
  - The Dream Upgrade view will be seen on the same popup as the End of Day

- End of Day Popup:
  - At the end of each day, show a popup with the following tabs:
    - Report
    - Dream Upgrades
  - End of Day Report:
    - At the end of each day, show a popup list summarizing the achievements for the day:
      - Fish caught
      - Amount of money earned
  - Dream Upgrades:
    - Similar to ShopView, but instead shows purchases for dream upgrades.
    - We'll need another shopGameplay and shopDisplay csv, but for dream upgrades.
- Economy:
  - We'll need to make sure dream points and upgrades are logged properly in the game economy
  - We may need to do a refactor of the Economy tab to reduce code re-use. There seems to be logic duplication for any type of Zustand store, such as the ShopStore

## Solution

**Day timer**: a new `dayStore` tracks wall-clock day progress independently of the fishing loop — `dayStartTime`, `dayNumber`, `phase` (`NIGHT` / `DAWN` / `SUNRISE`), and `isEndOfDay`. `DAY_DURATION_MS` (15 min) and the three phase boundaries (5 / 12 / 15 min) live in `constants.ts`. `InventoryView` renders a `Progress` bar (same primitive as `StatBar`) plus the phase label underneath, driven by a local interval that recomputes elapsed time from `dayStartTime` — the timer itself is derived, not stored as ticking state, so it survives re-renders and tab switches cleanly.

**Dream points as a threshold system**: dream points are earned from **money earned since the start of the current day** crossing a series of thresholds — structurally identical to how lure levels are earned from cumulative XP (`LURE_LEVEL_XP` / `computeLureLevel` / `applyLureXp` in `constants.ts`). Rather than duplicate that logic, `computeLureLevel` and `applyLureXp` are generalized into threshold-agnostic `computeLevelFromThresholds(thresholds, value)` / `applyThresholdGain(thresholds, current, gain)`, and both lure XP and dream points become thin callers of the shared function with their own threshold arrays (`LURE_LEVEL_XP` vs. a new `DREAM_POINT_MONEY_THRESHOLDS`). `dayStore` subscribes to `usePlayer`'s `wallet` field directly (the same "did the wallet just go up" diff `InventoryView` already does for its `+amount` popup) so no call sites in `PondView` need to know about dream points — any wallet increase, from any source, feeds the day's earnings counter and is run through the threshold function to award dream points.

**Reducing Zustand store duplication**: `shopStore` and the new dream-upgrade store need almost identical logic (load CSV catalog → track levels → price lookup → afford check → buy → debug level overrides → persist to `localStorage`), differing only in *which currency pays for it* and *which CSV catalog backs it*. Rather than copy-pasting `shopStore.ts`, that logic is extracted into a `createUpgradeStore(options)` factory — parameterized by a currency accessor/deductor pair and a `localStorage` key — that both `shopStore` (paying with `wallet`) and the new `dreamShopStore` (paying with `dreamPoints`) call to produce their store + actions. The stat-application switch (`LURE`, `HP`, `INVENTORY`, `ROD`, `ROD_SLOT`, `ROD_ATTACK`, `ROD_DEFENSE`, `BAIT`) is shared verbatim, since dream upgrades apply to the same underlying player stats as regular shop upgrades — they're just gated behind a different currency and only purchasable from the End-of-Day popup.

**Dream Upgrades catalog**: a new `DreamShopGameplay.csv` / `DreamShopDisplay.csv` pair, loaded through the same `loadShopData`/`parseShopGameplayRows` code path in `csvLoader.ts` generalized to take a `folder` + `displayFile` override instead of hardcoding `Shop`/`ShopDisplay.csv`.

**End of Day popup**: when `dayStore.isEndOfDay` flips true (timer elapsed), all active rod loops in `PondView` pause (no new casts/bites/timeouts tick) until the player dismisses the popup — mirroring how a rod slot already goes idle when its assignment is "None". A new `EndOfDayPopup` component renders as a fixed overlay (same positioning approach as the debug panel in `App.jsx`) with two Radix `Tabs`:
- **Report**: fish caught today and money earned today, both tracked directly on `dayStore` (`fishCaughtToday` incremented from `PondView.finishFight` alongside the existing XP/bait side effects, `moneyEarnedToday` from the wallet-diff subscription above).
- **Dream Upgrades**: visually identical to `ShopView` (reusing its grouping/pips presentation) but backed by `dreamShopStore` and priced in dream points instead of `CURRENCY_SYMBOL`.

A "Start Next Day" button calls `startNewDay()`, which resets `dayStartTime`, `moneyEarnedToday`, `fishCaughtToday`, and `isEndOfDay`, increments `dayNumber`, and un-pauses rods. Dream points and any dream upgrades already bought persist across the transition — nothing about the wallet, inventory, or regular shop progress resets at a day boundary; only the day timer and the day's own earnings/catch counters do.

```
PondView (wallet +$) ──► usePlayer wallet diff ──► dayStore.recordEarnings()
                                                         │
                                              moneyEarnedToday += diff
                                              dreamPoints += thresholdsCrossed
                                                         │
                                        elapsed >= DAY_DURATION_MS
                                                         │
                                                         ▼
                                              dayStore.isEndOfDay = true
                                                         │
                                        PondView rods pause · EndOfDayPopup opens
                                                 ┌───────┴────────┐
                                            Report tab      Dream Upgrades tab
                                        (fish/$ today)     (dreamShopStore, paid
                                                             in dream points)
                                                         │
                                              "Start Next Day" ──► startNewDay()
```

## Implementation Plan

### Phase 1 — Threshold generalization + constants
**`src/util/constants.ts`**:
- Extract `computeLevelFromThresholds(thresholds, value)` and `applyThresholdGain(thresholds, current, gain)` from the existing `computeLureLevel` / `applyLureXp` bodies. Reimplement `computeLureLevel` / `applyLureXp` as thin wrappers around these so lure-leveling behavior is unchanged.
- Add `DAY_DURATION_MS = 15 * 60 * 1000`.
- Add `DayPhase` enum (`NIGHT`, `DAWN`, `SUNRISE`) and `DAY_PHASE_BOUNDARIES_MS = [5, 12, 15].map(m => m * 60 * 1000)`.
- Add `DREAM_POINT_MONEY_THRESHOLDS` (array of cumulative-money requirements, same shape as `LURE_LEVEL_XP`) and a `computeDreamPoints(moneyEarnedToday)` helper built on `computeLevelFromThresholds`.

### Phase 2 — `dayStore`
**`src/stores/dayStore.ts`** (new): state — `dayNumber`, `dayStartTime`, `moneyEarnedToday`, `fishCaughtToday`, `dreamPoints`, `isEndOfDay`.
- `tickPhase(now)` — derives `DayPhase` from `now - dayStartTime` against `DAY_PHASE_BOUNDARIES_MS`; sets `isEndOfDay = true` once elapsed passes `DAY_DURATION_MS`.
- `recordEarnings(amount)` — bumps `moneyEarnedToday`, recomputes dream points via `computeDreamPoints`, adds the delta to `dreamPoints`.
- `recordCatch()` — increments `fishCaughtToday`.
- `startNewDay()` — resets `dayStartTime`, `moneyEarnedToday`, `fishCaughtToday`, `isEndOfDay`; increments `dayNumber`. Leaves `dreamPoints` untouched.
- On module init, `usePlayer.subscribe((s) => s.wallet, (wallet, prevWallet) => { if (wallet > prevWallet) recordEarnings(wallet - prevWallet); })` — reuses the increase-only diff pattern already in `InventoryView`.

### Phase 3 — Generic upgrade store factory
**`src/stores/upgradeStoreFactory.ts`** (new): pull the body of `shopStore.ts` (`initShopFromData`, `getUpgradePrice`, `canAffordUpgrade`, `isMaxed`, `buyUpgrade`, `setUpgradeLevelDebug`, `resetAllUpgradesDebug`, `localStorage` persistence) into `createUpgradeStore({ storageKey, getCurrency, deductCurrency })`, returning the same set of functions bound to that currency. The stat-application switch (`LURE`/`HP`/`INVENTORY`/`ROD`/`ROD_SLOT`/`ROD_ATTACK`/`ROD_DEFENSE`/`BAIT`) moves into a shared `applyStatEffect` used by both call sites.
- **`src/stores/shopStore.ts`**: becomes a thin instantiation — `createUpgradeStore({ storageKey: "debug_upgrade_levels", getCurrency: getWallet, deductCurrency: deductMoney })` — re-exporting the returned functions under their existing names so no import sites change.

### Phase 4 — Dream shop data + store
**`public/data/Dream/DreamShopGameplay.csv`** (new) and **`public/data/Dream/DreamShopDisplay.csv`** (new): same column shape as `ShopGameplay.csv` / `ShopDisplay.csv`.
**`src/util/csvLoader.ts`**: generalize `loadShopData` / `loadShopGameplayData` to accept a `{ folder, displayFile }` override (defaulting to today's `Shop` / `ShopDisplay.csv`) instead of hardcoding the path, so the same functions load the Dream catalog.
**`src/stores/dreamShopStore.ts`** (new): `createUpgradeStore({ storageKey: "debug_dream_upgrade_levels", getCurrency: () => useDayStore.getState().dreamPoints, deductCurrency: deductDreamPoints })`, loaded from the Dream CSV pair via the generalized loader.
**`src/stores/dayStore.ts`**: add `deductDreamPoints(amount)` action for the store above to call.

### Phase 5 — Day timer UI
**`src/components/InventoryView.tsx`**: add a day-timer block above the wallet display — a `Progress` bar showing time remaining in the day (recomputed from `dayStartTime` on a local interval, same rAF/interval approach already used for the animated wallet counter) with the current `DayPhase` label beneath it.

### Phase 6 — Catch/earnings hooks
**`src/components/PondView.tsx`**: in `finishFight`, on a win, call `dayStore.recordCatch()` alongside the existing `addLureXp` / `consumeBait` side effects.
- Gate each rod row's cast/bite/reel ticking on `!useDayStore((s) => s.isEndOfDay)` — same shape as the existing "rod slot assigned to None" pause check — so fishing freezes the instant the day ends and resumes after `startNewDay()`.

### Phase 7 — End of Day popup
**`src/components/EndOfDayPopup.tsx`** (new): fixed-position overlay, rendered from `App.jsx` when `useDayStore((s) => s.isEndOfDay)` is true (same overlay pattern as the existing debug panel). Radix `Tabs.Root` with:
- **Report tab**: reads `moneyEarnedToday` / `fishCaughtToday` from `dayStore`, rendered as a simple summary list.
- **Dream Upgrades tab**: same grouping/`LevelPips` presentation as `ShopView`, sourced from `dreamShopStore`'s upgrades and `dreamPoints` balance instead of `wallet`.
- "Start Next Day" button calling `startNewDay()`.

### Phase 8 — Economy Model
**`src/game/EconomyModel.ts`** (per the sync rule in `CLAUDE.md` — this mechanic changes both timing structure and money flow, so the model must track it):
- `simulateEconomy` gains a day-boundary check: track `cumulativeTime % DAY_DURATION_MS` (or an explicit `dayElapsed` accumulator alongside the existing `cumulativeTime`) and a `moneyEarnedToday` running total that resets whenever a day boundary is crossed mid-simulation.
- Add `dreamShopData: ShopUpgradeData[]` and `dreamPoints` tracking, mirroring the existing `levels` / `wallet` tracking for the regular shop.
- Generalize `cheapestUpgrade` / `pickUpgrade` / `applyUpgrade` to take a `(catalog, levels, currency)` tuple rather than being hardcoded to the wallet shop, so the same functions drive dream-upgrade purchasing at each simulated day boundary (always buy the cheapest affordable dream upgrade, same heuristic as the existing wallet strategy).
- **`EconomyRound`**: add `dayNumber: number`, `dreamPoints: number`, `moneyEarnedToday: number`, `dreamUpgradesBought: string[]`.

### Phase 9 — CSV Generator
**`src/components/model/CsvGenerator.tsx`**: add a `DreamShop` generation section mirroring the existing `generateShopRows`/`ShopGenerator` UI (its own `FunctionConfig` price curve, tier count, and "Download DreamShopGameplay.csv" button), so dream-upgrade pricing can be balanced the same way regular shop pricing is today.

### Test Plan

- Day timer counts down from 15:00 in `InventoryView`; the phase label switches Night → Dawn → Sunrise at the 5 min and 12 min marks.
- Earning money during a day accumulates toward dream point thresholds; crossing a threshold increments the dream point balance immediately (not only at day's end).
- When the 15-minute timer elapses, all active rods freeze mid-cast/mid-fight and the End of Day popup appears automatically without further player input.
- The Report tab shows fish-caught and money-earned totals matching what actually happened that day.
- The Dream Upgrades tab lists upgrades priced in dream points; buying one deducts from the dream point balance (not the wallet) and applies its effect immediately, same as a regular shop purchase.
- "Start Next Day" closes the popup, resets the timer and per-day counters, resumes paused rods, and leaves the wallet, inventory, regular shop levels, and dream point balance/upgrades untouched.
- In the Model tab, a multi-day economy simulation shows `dayNumber` advancing, `dreamPoints` accruing from `moneyEarnedToday`, and dream upgrades appearing in `upgradesBought`/`dreamUpgradesBought` logs alongside regular shop purchases.
